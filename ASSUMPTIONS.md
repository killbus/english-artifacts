# Assumptions Register

This file contains beliefs that are useful enough to guide experiments but are not yet established facts.

## Status vocabulary

- `UNVALIDATED` — plausible, but currently supported mainly by reasoning.
- `PARTIAL` — some evidence exists, but confidence is limited.
- `SUPPORTED` — repeated evidence supports the assumption.
- `REJECTED` — evidence is inconsistent with the assumption.

## A001 — English learners may value personal language artifacts

Status: `UNVALIDATED`

Hypothesis:

> Some Chinese English learners will perceive a reusable, personal, accumulative PDF as more valuable than another source of English knowledge.

Evidence:

- Existing low-ticket English journal / template products provide format-level evidence.
- No evidence yet establishes demand for our specific artifact concept.

Would falsify:

- Strong content interest but repeated refusal to purchase even at diagnostic pricing.
- Buyers download but consistently report no meaningful use.

Next test:

- First narrow artifact experiment.

## A002 — A static PDF can create a meaningful echo loop

Status: `UNVALIDATED`

Hypothesis:

> Cross-page return paths, personal IDs, comparison, and reuse can make a static PDF feel increasingly personal without dynamic software.

Would falsify:

- Users perceive the system as ordinary journaling or worksheet completion.
- Users rarely return to prior entries.

Next test:

- Prototype one artifact with an explicit Echo Contract and observe actual use.

## A003 — Users may pay for a specific artifact without wanting instruction

Status: `UNVALIDATED`

Hypothesis:

> A user can buy a PDF because it improves a recurring task, even when the product is not a course or lesson.

Would falsify:

- Purchase objections consistently ask for teaching / explanation rather than the artifact itself.

Next test:

- Separate product promise from educational promise in the first content experiment.

## A004 — Xiaohongshu can function as a demand-discovery layer

Status: `UNVALIDATED`

Hypothesis:

> Content can reveal user problems and create artifact demand without positioning the account as a teaching account.

Would falsify:

- Engagement remains detached from product problems.
- Comments show broad curiosity but little task-level pain.

Next test:

- Problem-led content with a concrete artifact CTA.
